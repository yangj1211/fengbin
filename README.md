# 丰宾电子 · 智能制造平台

提供登录、智能体广场、五个智能体、数据管理及简单用户管理的业务原型。平台有唯一超级管理员，其他账号由管理员创建，角色分为管理员和普通用户。五个智能体为客户与产品推荐、设备维修助手、能源预测与优化、生产洞察与预警、供应商绩效评估。

## 当前操作流程

客户、维修默认进入问答；能源、生产、供应商默认进入看板，并可切换至问答。看板支持范围筛选、图表查看、异常明细及 Excel 导出。点击“智能问答”打开对应智能体的问答页面。生产看板底部显示产线明细。所有阈值和权重使用当前固定规则。

问答支持推荐问题、连续追问、停止生成，以及按智能体独立的新建、搜索、切换、改名和删除会话。回答以普通文本逐步显示，可查看处理摘要、复制正文、点赞或点踩。文末引用可打开 PDF 原页或 CSV 预览，聊天与原文分别滚动。

数据管理以单一列表展示业务文件和数据表，支持搜索、类型/智能体筛选、分页、预览和确认删除。数据表可导出完整 Excel 明细。业务原型的资源删除标记保存在当前浏览器，历史引用保留名称并显示文件已删除。

## 登录与用户管理

- 用户使用账号和密码登录。服务端首次初始化创建唯一超级管理员，沿用现有管理员密码配置，账号为 `admin`。
- 普通用户仅能访问广场和五个智能体，保留业务引用阅读、看板及明细导出；整个“平台管理”分组隐藏，直接访问 `/data`、`/users` 也会被拦截。管理员可另行使用数据管理及用户管理。
- 用户管理显示姓名、账号、角色、创建时间、最近登录及操作，时间统一北京时间，支持姓名/账号搜索和 10 至 100 条分页。管理员新增用户时填写账号、初始密码和角色，默认普通用户；姓名选填，账号名唯一，保存时去首尾空格并转小写，创建后账号不可修改，密码为 8 至 64 个字符且需确认。超级管理员唯一且不可降级或删除，正在登录的账号不可删除。
- 编辑用户时密码留空不修改；管理员修改自己的密码必须输入旧密码，修改其他用户密码使用“重置密码”，无需对方旧密码。删除需二次确认。修改自己的姓名后更新导航显示；修改自己的密码后回到登录页。
- 所有用户的左下角账户菜单均有“修改密码”，验证旧密码、新密码和确认新密码后提交，成功回到登录页。删除账号或修改密码、角色会让其已有登录状态失效。

账号存储在服务端 D1 数据库 `AUTH_DB`，采用随机盐 PBKDF2 SHA-256 密码哈希。会话由独立密钥 HMAC 签名，Cookie 为 HttpOnly、SameSite=Strict，HTTPS 下启用 Secure。服务端保护工作区路由和用户管理接口；应用在切换目录、窗口聚焦及每分钟复核登录状态，失效后返回登录页。

本地管理员配置读取未提交的 `.dev.vars`：`ADMIN_USERNAME`、`ADMIN_PASSWORD_HASH`、`ADMIN_SESSION_SECRET`。数据库绑定由当前运行配置提供；生产环境需配置有效的持久数据库及上述密钥。超级管理员仅初始化一次，后续用户资料维护以数据库为准。

## 数据范围与账号隔离

业务结果目前由前端资料和本地规则生成，尚未连接真实模型或客户业务系统。能源提供时序明细；生产现有四条产线汇总，不虚构未提供的日期、班次、节拍、在制品或停机事件。详细流程和业务口径见 [PRODUCT.md](PRODUCT.md) 及 `docs/` 中各场景说明。最新需求文档：[PRD Markdown](docs/丰宾电子智能体PRD_简明版.md) · [PRD Word](docs/丰宾电子智能体PRD_简明版.docx)。

对话、草稿、反馈和看板偏好保存在当前浏览器的 localStorage，并按登录账号隔离；业务数据和资源删除标记在同一浏览器内共用。工作区先绑定已验证的账号身份，再加载个人记录。旧版本未区分账号的历史记录迁入超级管理员，其他账号不会读到。每段会话保留最近 20 轮问答，刷新后可恢复；这些业务记录不跨浏览器同步，服务端账号信息独立持久保存。

## 开发与验证

使用 Node.js 22.13+。本地 Cloudflare 启动：`npm run dev`；构建：`npm run build`；Vercel 构建：`npm run build:vercel`；类型和静态检查：`npx tsc --noEmit`、`npx oxlint app lib proxy.ts`。

## Vercel 部署

仓库中的 `vercel.json` 使用 Nitro 生成 Vercel Build Output API 产物；`proxy.ts` 由 vinext 在应用内执行。Vercel 使用 Node 账号适配器，支持通过 Marketplace 接入 Turso 持久账号库，也兼容服务端 D1 API。本地 Cloudflare 使用原来的 `AUTH_DB` 绑定。

首次部署需要设置账号和数据库环境变量，配置方法见 [Vercel 部署说明](docs/Vercel部署.md)。

`app/workspace.tsx` 负责身份加载和工作区，`app/application/` 包含智能体、看板、会话、数据管理、用户管理及浏览器持久化。根页及 `app/[...path]/page.tsx` 保护直接访问；目录切换使用 History API 保留业务页面状态。`lib/user-store.ts` 和 `app/api/auth/`、`app/api/users/` 处理账号及会话。

账号验证见 `tests/accounts.test.mjs`；浏览器记录隔离与旧数据迁移见 `tests/workspace-accounts.test.mjs`；维修场景和历史草稿兼容见 `tests/maintenance-engine.test.mjs`。各测试可用 `node <文件路径>` 单独运行。
