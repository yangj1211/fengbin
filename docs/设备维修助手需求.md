# 第二场景：设备维修助手

依据《卓越级智能工厂场景实例描述》的“设备维修方案 AI 智能推荐与优化”整理。

## 要解决的问题

维修手册、点检标准、故障代码、历史工单和备件经验分散。维修人员描述问题后，在同一对话中查资料，获得具体维修方案，并核对原文件。

## 使用流程

1. 输入设备名称或型号、故障代码、告警原文或异常现象；可补充发生工况、影响范围和已检查的结果。
2. 缺少信息先追问；型号、代码或现象不一致时先核对。不默认某台设备，不替用户选一个故障。
3. 核心输出是具体维修方案：先明确检查项和异常判据，再按检查结果给出对应处理动作、需要核对的备件、操作注意事项和修后验证方法。用户只问某一项时再单独回答。未提供依据时不推断根因、工时、库存或部件损坏结论。
4. 用户可继续追问、纠正现象或补充实际处理结果。同一故障保留上下文，切换设备或故障时重新核对。
5. 引用集中在回答末尾，显示文件名和页码；点击定位原页，可翻页查看。

## 回答样式

统一渲染普通 Markdown 文本，按问题使用段落、标题和列表。没有固定的维修结果卡片、指标、条件标签、步骤组件、表格、采用按钮或快捷追问。只问备件就回答备件，复合问题覆盖相应内容。旧对话保留正文，缺少原文件引用时如实说明。

## 前端样例范围

首页三个示例入口：生成维修方案、查询告警代码、查看备件与案例。

底层覆盖五个独立故障：卷绕机张力波动与断箔、含浸机真空不足、老化柜温度偏高、电容测试仪读数波动、空压机供气压力不足。型号、代码、工单和备件资料均为合成样例。五类设备与具体故障组合均属于本次演示选取，原文只要求不少于五个典型故障，未指定清单。

提供三份示例 PDF：维修手册、历史工单、备件与维修 FAQ，包含原文页预览。

## 当前边界

本阶段只完成前端与样例交互，不新增后端能力。后续智能体及数据使用现有平台。当前不包含实时诊断、设备控制、EAM/CMMS 集成、真实工单创建或关闭；反馈保存在当前浏览器的对话中。现场维修仍需人员确认，不能把建议当作自动诊断结论。

## 核对重点

- 五类故障均包含明确处理动作和修后验证方法，有可定位的文件依据；不止输出检查方向。
- 只说设备、缺型号、未知代码和信息冲突时不会生成虚构现场结论。
- 先说现象、后补型号可以接续；更换设备不带入上一台设备的故障。
- 追问备件、原因、历史案例或多个问题时，内容与提问一致。
- 对话历史、原文定位及旧记录可继续使用。
